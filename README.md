# Markov Health OS v1.1.0

**Markov Health OS** — local-first персональная операционная система для системного управления данными о здоровье, физической форме, восстановлении, анализах, образе жизни и целях.

**Product concept & development — Pavel Markov.**

Концептуально вдохновлено open-source проектом [Health-OS](https://github.com/alxyrgin/health-os). Код Health-OS в этой реализации не используется; интерфейс, архитектура и продуктовая логика Markov Health OS реализованы самостоятельно.

## Возможности

- Полностью статическое приложение: HTML + CSS + Vanilla JavaScript + Browser APIs.
- Без backend, базы данных, регистрации и обязательных внешних API.
- Пошаговый onboarding с сохранением незавершённого черновика.
- Персонализированный dashboard на основе главной цели пользователя.
- Ключевые показатели, «Что изменилось», «Сегодня», детерминированные сигналы, Health Score и персонализированное качество данных.
- Тело: вес, процент жира, талия, пульс в покое, давление, SpO₂ и температура.
- Сон, активность, тренировки и дневные агрегаты питания.
- Анализы с пользовательскими референсами, статусами и трендами повторных измерений.
- Лекарства, добавки, симптомы, цели и заметки.
- Единая History/Timeline, фильтры, Quick Add и глобальный поиск (`Ctrl/Cmd + K`).
- Несколько локальных профилей с изоляцией всех записей по `profileId`.
- Demo Mode с полностью вымышленными данными, не затрагивающий реальные профили.
- Light / Dark / System theme и отключаемые модули.
- JSON backup с проверкой структуры при импорте и защитой от destructive import.
- Опциональная защищённая резервная копия `.mhos` через Web Crypto API: PBKDF2-SHA256 + AES-GCM.
- CSV export для веса, давления, сна, анализов, активности и целей.
- Health Brief для передачи выбранных данных во внешний AI-инструмент вручную.
- Consultation Brief с Copy, TXT и Print / Save as PDF.
- Installable PWA и offline application shell в поддерживаемых браузерах.
- Адаптивный desktop/mobile UX и GitHub Pages-compatible относительные пути.

## Architecture

- HTML + CSS + Vanilla JavaScript.
- Local-first: основной state хранится в браузере.
- Без backend, обязательного аккаунта и обязательного API.
- Один читаемый `app.js` без bundler/runtime dependencies; код организован по доменным секциям.
- PWA Service Worker кэширует только application shell.

## Data model

Основной объект `markovHealthOSData` содержит schema version, активный профиль, профили, измерения тела, анализы, лекарства, добавки, симптомы, сон, активность, тренировки, питание, цели, заметки и настройки. Каждая пользовательская запись содержит `profileId`; расчёты и экраны фильтруют данные по активному профилю.

## Security & privacy

- Пользовательский текст создаётся через безопасные DOM API и `textContent`; динамические данные не исполняются как HTML.
- CSP ограничивает источники скриптов, стилей, изображений и подключений.
- CSV-экспорт нейтрализует formula-like пользовательские строки.
- Import использует strict schema validation и отклоняет duplicate/orphan IDs и неподдерживаемую future schema.
- `.mhos` использует PBKDF2-SHA256 + AES-GCM через Web Crypto API.

## Backup strategy

1. JSON — полный переносимый backup, **не зашифрованный**. Храните его как чувствительные персональные данные.
2. `.mhos` — защищённая копия с пользовательским паролем. Пароль невозможно восстановить через приложение.
3. CSV — формат совместимости отдельных наборов, а не backup.
4. Перед destructive import приложение создаёт временную safety copy и проверяет записанный state после импорта.

## Privacy model

Основные пользовательские данные хранятся в `localStorage` браузера под ключом:

```text
markovHealthOSData
```

Markov Health OS v1.1.0 не содержит серверной базы данных, аналитических SDK, обязательной телеметрии или аккаунтов и не отправляет медицинские записи разработчику.

Service Worker, если браузер его поддерживает, кэширует только статические файлы приложения для offline-запуска. Он не переносит health records из `localStorage` в облако или на сервер.

Подробнее: [Privacy](./privacy.html).

## Local storage и сохранность данных

- App version: `1.1.0`.
- Current data schema: `version: 2`.
- Запись выполняется через централизованный storage layer с проверкой сериализованного значения.
- При ошибке сохранения изменение откатывается к последнему подтверждённому persistent state.
- Import сначала проверяется и только после подтверждения заменяет локальный state.
- Перед destructive import создаётся локальная safety copy для rollback текущей операции.

`localStorage` не является заменой полноценному серверному хранилищу. Очистка данных сайта/браузера, сброс browser profile или потеря устройства могут удалить данные, поэтому для важных записей регулярно создавайте резервные копии.

## Backup и восстановление

### Обычная резервная копия

В **Настройки → Данные** выберите экспорт JSON. Создаётся файл:

```text
markov-health-os-backup-YYYY-MM-DD.json
```

Файл содержит metadata, schema version, профили и записи приложения.

### Защищённая резервная копия

При наличии Web Crypto API можно создать:

```text
markov-health-os-backup-YYYY-MM-DD.mhos
```

Данные шифруются локально с паролем пользователя. Пароль и производный ключ не сохраняются приложением. Потерянный пароль невозможно восстановить через Markov Health OS.

### Импорт

Перед заменой текущих данных приложение проверяет структуру, schema version, IDs, `profileId`, даты, числовые поля и основные enum-значения и показывает preview содержимого. Future schema и повреждённые backup отклоняются без изменения текущего state.

## CSV export

CSV — формат совместимости, а не резервная копия. Доступен экспорт отдельных наборов данных для Excel, Google Sheets, R/Python и других инструментов. Для полного восстановления используйте JSON или `.mhos`.

## Health Brief и Consultation Brief

Оба brief формируются локально. Приложение само не отправляет их в ChatGPT, врачу или другому сервису.

- **Health Brief**: структурированный текст для ручного копирования во внешний инструмент.
- **Consultation Brief**: структурированная сводка, которую можно копировать, скачать как TXT или распечатать / сохранить как PDF средствами браузера.

После самостоятельной передачи brief внешнему сервису применяются правила конфиденциальности этого сервиса.

## Как запустить локально

### Способ 1 — открыть файл

Откройте `index.html` в современном браузере.

Некоторые браузеры ограничивают Service Worker, clipboard или отдельные download-функции при запуске через `file://`.

### Способ 2 — простой статический сервер

```bash
python -m http.server 8000
```

Откройте:

```text
http://localhost:8000/
```

Если Node.js уже установлен, альтернативно можно использовать:

```bash
npx serve
```

Node.js/npm **не являются runtime-зависимостями** приложения.

## GitHub Pages deployment

1. Создайте GitHub repository, например `markov-health-os`.
2. Загрузите содержимое проекта в корень branch `main`.
3. Откройте **Settings → Pages**.
4. В **Build and deployment** выберите **Deploy from a branch**.
5. Выберите **main** и **/(root)**.
6. Нажмите **Save**.
7. Откройте `https://USERNAME.github.io/REPOSITORY/` после публикации.

GitHub Actions не требуются. Все внутренние пути приложения относительные и рассчитаны на публикацию в subdirectory GitHub Pages.

## Установка как PWA

При публикации по HTTPS в поддерживаемом браузере приложение может быть установлено как PWA. Manifest и Service Worker используют относительные пути и работают в scope репозитория.

Offline mode относится к application shell. Данные пользователя продолжают храниться локально в browser storage.

## Known limitations / ограничения

- Нет cloud sync и серверного аккаунта.
- Нет автоматического импорта из Apple Health, Health Connect, Garmin, Amazfit, лабораторий или клиник.
- Нет встроенного AI API.
- Лабораторные единицы не конвертируются автоматически.
- Health Score не является медицинским score.
- Лабораторные статусы сравнивают значение только с референсами, введёнными пользователем.

## Release integrity

Файл `RELEASE-MANIFEST.sha256` содержит SHA-256 контрольные суммы production-файлов релиза (кроме самого manifest). После сборки ZIP проверяется повторным распаковыванием и рекурсивным сравнением с замороженным source.
